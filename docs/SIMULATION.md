# ローカルの人工回答検証

実回答や本番DBを使わず、1試行1,000人・現在の40意見で分析と意見の抽選を検証します。生成確率は番号に沿って人工的に設定しており、市民の意見や各政策への支持を推定するものではありません。

```sh
npm run simulate:polis
npm run tune:polis
```

`simulate:polis` は調整前の設定を固定して再現するベースライン検証、`tune:polis` は旧設定と現在の既定値を比較する検証です。比較結果と調整方針は `outputs/polis-tuning/` と [TUNING.md](TUNING.md) に保存します。

TypeScriptを直接実行できるNode（確認環境v26）とPythonのmatplotlibを使用。16条件を各10シードで実行し、82通りの設定比較、35試行の別シード検証、境界ケースを出力します。結果はgit管理・ソース配布から除外された `outputs/polis-simulation/` に保存されます。`report.html` が図入りレポート、`results.json` が全結果・既定値・実装SHA-256、`fixture-three.json` 等が生成回答です。`SIMULATION_REPEATS` と `SIMULATION_OUTPUT` で反復数と出力先を変更できます。レポートの判断文は標準シナリオの検証結果を説明するもので、新しいシナリオに変える際は見直してください。

## 実際の画面で確認

```sh
npx vinext build
npm run preview:simulation -- outputs/polis-simulation/fixture-three.json --port 5185
```

別の空のD1/R2・仮の認証情報を `.wrangler/simulations/run-*/` に作り、生成回答を入れて `127.0.0.1` のみで起動します。通常の `.wrangler/state`、実回答、運営用の秘密情報は使いません。起動後の画面で「共通する意見を見る」を選択します。APIと全40意見の4種回答カウンターも生成データと照合します。

画面自体は本体のUIなので人工データの帯を付けていません。人工データ専用のURLとして扱ってください。停止は起動した端末のCtrl+C。`--verify-only` はAPI確認後に終了します。既存サーバーを停止・再利用せず、使用中のポートなら失敗します。ここからデプロイは行いません。

## 調整する場所

`lib/polis-math.ts` の `DEFAULT_ANALYSIS_OPTIONS` に現在の暫定値を集約しています。`analyzeAccumulated(acc, overrides)` または `analyze(votes, ids, mine, overrides)` に実験用の値を渡せます。診断値は `analysis` と別に返します。保存版には計算の版と全設定を記録し、設定を変えると古いキャッシュを再利用せず再計算します。実験コードの `sweeps` と `scenarios` を変更して比較できます。

明瞭な群はよく再現する一方、旧設定0.2では無構造の回答にも群が付き、2%の少数派を復元できませんでした。2026-09-18の暫定調整で、分析対象80セッション以上・分離度0.45以上を採用し、共通点は各群10回答以上・賛成60%以上に加え、Wilson下限（z=1.96）が50%を超えることを求めます。連続分布にも群を付ける問題は残ります。境界ケースには、孤立した1人で全体が保留になる問題、旧設定で3人群の2人賛成を共通点にする問題（今回抑制）、パスの傾向だけで群が分かれる例もあります。

固定シード・入力順不変性・分類一致度・群別の一致度・共通点の精度と再現率を確認しています。実データでの妥当性や本番の同時アクセス性能を保証するものではありません。
