# Polis パラメータの暫定調整

実データが集まる前の初期値として、群の誤表示と少数回答だけでの共通点の断定を抑える。今回の人工データへの適合を「最適化」とは扱わない。アプリ既定値は `lib/polis-math.ts` の `DEFAULT_ANALYSIS_OPTIONS` にまとめてあり、実験時には `analyzeAccumulated` のオプションで上書きできる。

## 採用した初期値

|パラメータ|旧値|現行値|判断|
|---|---:|---:|---|
|`minSilhouette`|0.2|0.45|同じ回答を群に分けた候補のうち、分離が弱い結果の表示を保留する|
|`minSessions`|8|80|分析対象の匿名セッションが80に達するまで群表示を待つ|
|`minBridgeVotes`|3|10|各群での回答数を確保する。小群そのものを消す条件にはしない|
|`minBridgeAgreement`|0.6|0.6|各群の観測賛成率が60%以上という意味を維持する|
|`bridgeWilsonZ`|なし|1.96|各群のWilson下限を計算し、少数回答の不確実性を考慮する|
|`minBridgeLowerBound`|なし|0.5|全群でWilson下限が50%を超えるときに共通点として表示する|

PCA反復100、k-means反復60、開始点4、最大群数4、最小群人数3、分析資格の賛否回答6件は据え置く。小群に十分な共通点の根拠がないことと、小群そのものが存在しないことを混同しない。

少人数のランダム回答は0.4でも群に分かれやすかった。開始を80対象セッションに遅らせ、分離度0.45を暫定採用する。これにより境界付近の弱い3群も1,000人の10回中1回は保留した（別5シードでは5回とも表示、計14/15）。明瞭な早期の群も80対象セッションになるまで待つという運用上の選択であり、80や0.45が普遍的な最適値という根拠はない。

共通点の条件は各群で **回答10件以上、観測賛成率60%以上、Wilson下限が50%を超えること** をすべて満たすこと。パスは分母に含み、無関係・欠損は含まない。2/3賛成、6/10賛成、8/10賛成はいずれも通過しない。15/20賛成のWilson下限は約0.531なので通過する。大きなサンプルでは60%という観測率条件が主になる。

ここで用いるWilson下限は、固定した群・独立な二項応答というモデルで、両側95%区間の下端に相当する計算である。「母集団の賛成率が60%以上」と保証するものでも、推定した群・複数の意見・適応的提示を補正した検定でもない。人為的な回答での過大表示を減らすための追加条件として使う。

各群20回答も比較するが、初期段階や小群の共通点が長く表示されなくなる。10回答とWilson下限を併用する値は、根拠と立ち上がりの両方を考えた暫定的な運用判断である。

## 再現可能な比較

```sh
npm run tune:polis
npm run simulate:polis:edges
```

`outputs/polis-tuning/before-after.json` に全設定、シード、シナリオ別結果、人数、ARI、共通点の適合率・再現率、ソースのSHA-256を保存する。読みやすい比較は同じフォルダの `REPORT.md`。

- 1,000人、16条件、10シードで旧設定・分離度だけ0.4・現行設定・各群20回答の4設定を同じ回答に適用する。
- 上と異なる5シード、7条件でも比較する。これら5シードは過去のレポートですでに確認しており、今回は完全に未使用の検証データではない。
- 立ち上がりは20・40・80・160・1,000人、8条件、最初のシードを使う。3群、弱い群、90対10、98対2、疎な回答、新規意見、ランダムに加え、共通点1件の少数群の回答を最大3件に制限した条件も比較する。各人数で独立に生成するため、1つの会話の時系列ではない。
- 条件ごとに4設定を比較するため、基本比較は合計940回の分析を実行する。生成した回答はすべて人工データであり、通信・DB書き込み・公開は行わない。
- 追加で8・20・40・60・80・100・160人×3条件×10シード×2方式（独立生成／同じ1,000人の先頭N人）を比較した420回の結果は `startup-grid.json` に固定保存する。これは分離度0.4・最低8対象の探索結果。現行の80対象・0.45の条件を保存された候補に適用した比較も出力する。ファイルがない出力先では同じ固定設定で再生成する。
- さらに初めて使う5シード（90,000,001 + 1,009×反復番号）、各80人でランダム・意見別賛成率・明瞭な3群を確認する（15回）。この少数の検証でも一般的な誤検出率は保証しない。

`npm run simulate:polis` は**変更前の固定設定**を再現するための従来ベンチマーク。`LEGACY_ANALYSIS_OPTIONS` はこの比較専用であり、アプリに読み込まない。調整前のレポート一式は `outputs/polis-baseline-2026-09-18-before-tuning/` に保存している。

新しい比較スクリプトは、その旧記録と群数・状態・人数・分離度・ARI・共通点IDが一致することも確認する。計算時間、作成日時、診断項目の追加は完全一致の対象に含めない。

## 実データでの調整

実データでは正解の群数が分からないので、「きれいな群が出る」ことを目的に閾値を下げない。次の項目を一緒に確認してから一度に一つの設定を変える。

1. **参加の量と偏り。** 分析対象人数だけでなく、回答資格から外れた人数、回答数の分布、意見ごとの回答数、群ごとの回答数、提示確率を確認する。匿名セッションを実人数と見なさない。
2. **表示の安定性。** 回答の一部を除いた場合、別の時間帯に得た回答、回答数の差を小さくした場合で群の構成と共通点がどれだけ変わるかを見る。同一参加者の反復測定を独立回答として扱わない。
3. **小群と共通点。** 群数や全体平均だけでなく、小群の人数と回答数を確認する。共通点の除外理由を、率不足・回答不足・Wilson下限不足に分ける。率が高くても根拠不足なら保留を許す。
4. **調整と評価を分ける。** 設定を決めるデータ期間と、決めた設定を確認する後の期間を分け、変更前後を同じ保存データで比較する。新しい期間を見て設定を再調整したら、その期間は以後「未使用の検証データ」ではない。
5. **比較記録を残す。** 設定、実装バージョン、対象期間、適格人数、群数、最小群人数、保留理由、共通点の群別根拠を運営用の非公開記録に保存する。公開データや公開リポジトリへ原データを移さない。

保留が多い理由が回答の重なり不足なら、silhouette閾値を下げても解決しない。回答の導線・提示方式を先に確認する。群は「回答傾向が似た匿名セッションのまとまり」として読み、社会集団や住民の総意と同一視しない。

## 今回解決しない点

- 連続的に意見が変わる集団でも群に分かれる場合がある。silhouetteは離散的な真の集団の存在証明ではない。
- 人工の98対2条件では少数派を復元できず、今回の設定は誤分類の表示を保留する。
- パスの使い方だけで群が分かれることがある。
- 回答の重なりが少ない1人の追加により、他の多数の分類も保留する場合がある。
- 1,000人のランダム条件の結果は、小規模な集団や別の生成モデルへそのまま一般化できない。4設定を比較する立ち上がりの表は各条件1シードであり、追加420回と新しい5シードも同じ生成モデル内の確認である。実データの誤検出率の推定ではない。
